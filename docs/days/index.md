# The four-day plan

Each day is roughly **6 hours** of work: about 60% hands-on notebook time, 30%
reading and discussion, 10% breaks. The plan assumes a workshop setting but
works equally well self-paced — in which case treat each "day" as a session and
take as long as you need.

## How to work through it

1. **Read the day page first.** It tells you what the point of the day is.
2. **Run every cell.** Reading code is not learning code.
3. **Do the exercises.** They are marked `> **Exercise**` in the notebooks. The
   exercises are where the learning actually happens.
4. **Answer the checkpoint questions** at the end of each notebook, out loud or
   in writing. If you cannot, go back.
5. **Write your numbers down.** Tokens/second, recall@3, evaluation scores.
   You will want to compare them later.

## If you fall behind

The notebooks are ordered by dependency, but not all are equally essential.
If time is short, this is the priority order:

| Priority | Notebooks | Why |
|---|---|---|
| **Essential** | 01, 03, 07, 09, 10 | foundations, generation, tools, RAG, agents |
| **Important** | 02, 04, 06, 12 | hardware, decoding, serving, capstone |
| **Valuable** | 05, 08 | quantization, embeddings |
| **Optional** | 11 | fine-tuning — read it even if you cannot run it |
